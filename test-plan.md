# Test Plan

## 1. Project Overview

This project focuses on manual testing of the SauceDemo web application.

The purpose of this project is to evaluate the application's functionality, identify potential defects, and document test results.

The testing process includes login, product listing, sorting, shopping cart, checkout, user account behavior, navigation, and boundary value scenarios.

## 2. Test Objectives

The main objectives of this testing project are:

- To verify that users can log in with valid credentials.
- To verify that invalid login attempts display appropriate error messages.
- To test product listing and sorting functionalities.
- To verify adding and removing products from the shopping cart.
- To test the checkout process from start to finish.
- To identify and document functional defects.
- To evaluate the application's behavior with different user accounts.
- To verify logout and navigation functionality.
- To evaluate checkout form validation using boundary value test data.

## 3. Scope of Testing

The following functionalities are included in the testing scope:

- Login and logout functionality
- Product listing information (names, descriptions, prices, and images)
- Product sorting functionality
- Adding and removing products from the shopping cart
- Shopping cart validation
- Checkout process
- Different user account behaviors
- Navigation and error message validation
- Boundary value testing for checkout inputs

## 4. Out of Scope

The following areas are excluded from this testing project:

- Performance and load testing
- Security testing
- Source code review
- Database testing
- API testing
- Cross-browser compatibility testing

## 5. Test Environment

- **Application:** SauceDemo
- **Test URL:** https://www.saucedemo.com/
- **Operating System:** Windows
- **Browser:** Google Chrome
- **Testing Type:** Manual Testing
- **Testing Device:** Desktop Computer

## 6. Test Approach

The testing process will follow a manual testing approach.

- Test cases will be designed based on the application's expected behavior.
- Positive and negative test scenarios will be included.
- Boundary value scenarios will be considered where applicable.
- Test cases will be executed manually.
- Actual results will be compared with expected results.
- Failed test cases and identified issues will be documented with expected results, actual results, and available evidence.
- Screenshots will be added as evidence when necessary.

## 7. Entry and Exit Criteria

### Entry Criteria

- The SauceDemo application is accessible.
- Valid and invalid test user credentials are available.
- The test environment is ready.
- Test cases are prepared.

### Exit Criteria

- All planned test cases have been executed.
- Test results have been documented.
- All failed test cases and identified issues have been documented.
- Test execution summary has been prepared.

## 8. Risks and Assumptions

### Risks

- Slow application response times may affect test execution.
- Different user accounts may exhibit different application behaviors.
- Application behavior may change during testing.

### Assumptions

- The SauceDemo application is available during testing.
- Test user credentials provided by the application are valid.
- The application is tested using Google Chrome on Windows.
